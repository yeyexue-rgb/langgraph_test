1. 第 2 篇来了：别再把 Agent 当接口测！五维判定框架，一图看懂。

7. 维度三 · 行为合理性：结果对 ≠ 过程对，轨迹里见真章。
8. 维度四 · 安全合规性：防注入、防越权、防泄密，高风险操作要确认。
9. 维度五 · 稳定与终止性：每次都差不多，而且永远停得下来。

## 五、正文 · 长版（图文消息用，每张图前配一段）

**引子**
> 上篇讲了 Agent 为什么"测不准"，评论区炸出一堆同款遭遇：90 分上线、一周翻车的不止一家。这篇直接给解法——不碰源码，怎么判断一个 Agent"到底行不行"。五把尺子，量完就有结论。

**[图 2] 先回到那个翻车的客服 Agent**
> 内部测试 90 多分，Demo 行云流水，上线一周工单炸了，分数却还是 90 多。问题不在模型，在团队没有一套方法判断它"行不行"。这套方法，就是今天的五维判定框架。

**[图 3] 测 Agent，先把它当黑盒**
> 你测微信不用读微信源码，测 Agent 也一样。黑盒视角下，Agent = 输入 → 做了什么 → 输出 → 留下的轨迹。判定就一句话：在给定输入、上下文和环境下，它是否产生了正确、安全、稳定且可追踪的行为。

**[图 4] 五维总览：五把尺子一次记牢**
> 结果正确性问"事办成了吗"，数据可信性问"说的是真的吗"，行为合理性问"事办得对吗"，安全合规性问"越界了吗"，稳定与终止性问"停得下来吗"。五维是"与"的关系，挂一维都不能上线。

**[图 5] 维度一 · 结果正确性**
> 新手最爱写 `assert "已为您下单" in resp`——模型换个说法就误报。正确姿势是分层验：关键事实、必含字段、禁止内容、Schema、语义一致。断"事办没办成"，别断"话怎么说"。

**[图 6] 维度二 · 数据可信性**
> Agent 翻车第二现场：一本正经地胡说。物流接口超时，它敢答"您的订单已签收，签收人：前台"。测试时注入接口失败场景，断言它必须明说失败，不许编。查不到就明说，拿不准别装懂。

**[图 7] 维度三 · 行为合理性**
> Agent 会动手：调 API、改数据。该调工具时不调、不该调时乱调、顺序颠倒、重复调用——只看最终回答永远发现不了，把轨迹拉出来逐步骤审。结果对 ≠ 过程对。

**[图 8] 维度四 · 安全合规性**
> 权限给 Agent 了，谁来管住它？跨租户越权、提示注入、敏感信息外吐、高风险操作不确认，全是传统 QA 没测过的新雷区。测试口诀：能力越大，越要测它"不该干什么"。

**[图 9] 维度五 · 稳定与终止性**
> 概率系统 + 自主系统 = 必须测两件事：稳不稳、停不停得下。同一用例跑 10 遍看成功率和方差；死循环防护、轮数上限、超时上限、重试有界——跑得对不算完，还得每次都差不多、永远停得下来。

**[图 10] 落地：一条用例，五个检查点**
> 用例模板直接抄：前置条件 + 输入 + 五维预期 + 结论。配套速查清单每次测前过一遍。模板和实操演示都打包好了，后台回复「agent」领取。
