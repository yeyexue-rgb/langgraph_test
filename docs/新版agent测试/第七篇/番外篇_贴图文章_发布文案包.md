## 三、正文 · 短版（图片消息用，放在第一张图前）

"让你测一个 AI Agent，你会怎么做？"

这个问题，正在从"加分题"变成"必考题"。而真实考场上的画面是：**十几个人里，答到点上的不超过两个。**

多数人的答案长这样：
- "加个重试，加个兜底话术"（只谈技术动作，没有质量框架）
- "把它当普通接口测，写断言就行"（完全没意识到 Agent 的特殊性）
- 名词堆一堆（ReAct、CoT……一追问就露馅）

问题出在哪？**这道题考的不是"你会不会用工具"，而是"你有没有一套质量思维框架"。**

而这，恰恰是测试工程师的主场——前提是，你得知道怎么把话说出来。

这篇给你三样东西：
**① 五步回答框架（背下来）② 60 秒口播稿（直接说）③ 五个送命追问的标准答案（接得住）**

迷茫解决不了问题，但准备可以。评论区聊聊：你被问过最难的 Agent 面试题是什么？

## 五、正文 · 长版（图文消息用，每张图前配一段）

**引子**
> 系列写了六篇"怎么测"，最后一篇解决"怎么说"。这道题会越来越常考，而多数人答不到点上——不是能力问题，是没准备好"说法"。

**[图 2] 两个真实的考场画面**
> 一个问"Agent 调用失败怎么兜底"，答"加重试"的当场出局；一个问"你会怎么测 AI Agent"，十几个人里答到点上的不到两个。共同问题：把 Agent 当普通接口测，没有质量框架。

**[图 3] 考官在考什么**
> 三样：有没有框架（50%）、懂不懂 Agent 特殊性（30%）、能不能落地（20%）。还有一条减分动作——听完就答。高手会先问："什么场景？准确率和安全要求什么级别？"先对齐，再作答。

**[图 4] 五步回答框架**
> ① 对齐：场景、用户、风险偏好；② 判定：五维框架（结果/数据/行为/安全/稳定）；③ 过程：看轨迹；④ 批量：评测集 + 自动评分 + CI；⑤ 上线：监控、回放、安全红队。

**[图 5] 一句话总纲**
> "结果看轨迹，选型看基准，上线看评测集。"——这句话撑起整个回答。展开讲，能讲十分钟；面试官挑任何一句追问，你都接得住。

**[图 6] 为什么是你**
> 测试工程师的五项老本行全是优势：用例设计 → 评测集；断言思维 → 检查点；环境搭建 → 替身；监控经验 → 回放；破坏性思维 → 安全红队。**你不是外行，你是专业对口。**

**[图 7] 四个加分项**
> 主动提安全（注入/越权）、主动提数据（4.2 倍故障率）、主动提成本（替身降本）、主动提落地（20 条用例一周闭环）。每说出一个，面试官的眼睛都会亮一下。

**[图 8] 五个送命追问**
> 没标准答案怎么断言？时好时坏怎么办？用例哪来？怎么防注入？你做过吗？——每个都有标准答案（见图）。记住：**讲细节、讲证据、讲"我"的动作。**

**[图 9] 三种反面教材**
> 只谈技术动作、当普通接口测、名词堆砌——三类答法全会被淘汰。自检标准：你的回答里，有没有"我"的具体动作？

**[图 10] 收官：3 天速成 + 三个反问**
> Day1 背框架、Day2 备案例、Day3 练口播；面试结尾反问三个问题（评测集谁维护？有轨迹留存吗？上线有卡点清单吗？）——问完，面试官就知道：这人是来干活的。
